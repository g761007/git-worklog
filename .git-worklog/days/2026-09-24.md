## 主要異動

### 新增 git-worklog view：把 worklog 渲染成單檔唯讀網頁（v1.3.0）

- **異動內容：** 新增 `view` 子命令，讀取 `.git-worklog` 的日檔與 index，產生一個自含的 HTML 頁面並以瀏覽器開啟。整個頁面唯讀，不寫入 repository 或 worklog 目錄。這是當天的主體工作，經 PR #37 合併後發為 1.3.0。
- **程式碼行為：** 使用者可執行 `git-worklog view`（可加 `--repo`、`--dir`、`--output`、`--no-open`），預設把頁面寫到 `~/.git-worklog/view/<project>-<hash>.html`，每次同一檔名，重跑並重新整理分頁即更新。若 `--output` 指向 worklog 目錄內會被拒絕並回傳 `OUTPUT_INSIDE_WORKLOG`；瀏覽器無法開啟時只給 `BROWSER_NOT_OPENED` 警告而不失敗。輸出檔為 owner-only 權限。
- **實作方式：** `git_worklog/cli/view.py` 的 `run` 負責參數檢查、呼叫 `viewer.build`、用 `writer.atomic_write` 寫檔，`_default_output` 以 worklog 所在專案名加路徑雜湊命名，`_inside` 判斷輸出是否落在 worklog 內，`_open_quietly` 在開瀏覽器期間把 stdout 導向 stderr，且在 Linux 無顯示環境時不啟動終端機瀏覽器，確保 JSON 契約不被污染。`git_worklog/cli/__init__.py` 新增 `view` 的 parser 與分派；`git_worklog/paths.py` 新增 `VIEW_SUBDIR` 與 `view_dir`。`git_worklog/viewer.py` 的 `build` 以結構（`##`/`###`，且感知 code fence）而非標題文字切分日檔，由 `split_sections`、`lead_of`、`load_day` 組成，commit 數量沿用 `cited_hashes` 以免與 `report` 不一致；`_page` 輸出含總覽、日曆、時間軸與每日文章的頁面，導覽用 CSS `:target`，唯一的 script 只負責搜尋與快捷鍵，並以 `script_hash` 算出 sha256 寫進 Content-Security-Policy（`default-src 'none'`，只允許該 script）。`git_worklog/mdhtml.py` 是自寫的安全 Markdown 轉 HTML：先對所有字元 escape，只輸出自己加的標籤，只允許 http(s) 與日檔連結，刻意不支援底線強調與 `javascript:`、`//host` 連結。
- **影響範圍：** 讀 worklog 多了一個瀏覽器介面，且不增加任何第三方依賴，整個頁面的 CSS 與 JS 都在模組內，所以解壓縮的 skill 也能直接執行。頁面內嵌整份 worklog（包含引用的原始碼片段），因此檔案設為 owner-only，CLI 輸出的 `note` 也提醒分享範圍。
- **相關檔案：** `git-worklog/git_worklog/cli/__init__.py`、`git-worklog/git_worklog/cli/view.py`、`git-worklog/git_worklog/mdhtml.py`、`git-worklog/git_worklog/paths.py`、`git-worklog/git_worklog/viewer.py`
- **相關 commits：** baf30ed (Daniel Hsieh) feat(view): show the worklog as one self-contained web page；36bcf82 (Daniel Hsieh) Merge pull request #37 from g761007/feat/view-command
- **測試與驗證：** tests/test_view.py — 惡意文字不會變成標記、連結只放行 http(s) 與日檔、NUL 不能偽造佔位符、fence 內的標題視為程式碼；tests/test_view.py — 頁面的 CSP 只允許內嵌的那一個 script、每日都有文章、損毀或非 UTF-8 日檔仍能顯示其他日；tests/test_view.py — view 命令寫出 owner-only 頁面、缺少 worklog 回 NOT_FOUND、拒絕寫進 worklog、不碰 repository、瀏覽器不會污染 JSON、連續執行位元組相同
- **相容性與風險：** 自寫的 Markdown 渲染器只支援 worklog 格式用到的語法，表格、引用區塊等會以純文字顯示，閱讀效果較樸素。；頁面內含整份 worklog 與原始碼引文，若被分享出去可能外洩私有程式碼，目前靠 owner-only 權限與 note 提醒。；搜尋與快捷鍵的 JS 沒有自動化測試，依賴人工在瀏覽器驗證。
- **維護注意事項：** 頁面統計描述的是 worklog 而非 repository：空白日曆格無法區分缺口與無 commit 的日子，要分辨需用 `coverage`。；日標頭的 Branch/HEAD 刻意不顯示，因為它記錄的是寫檔那次執行，同批分析的多天會有相同 HEAD。

### view 加入亮暗主題切換與 commit hash 複製徽章（v1.3.1）

- **異動內容：** 在 1.3.0 的頁面上補上右上角的亮/暗切換，以及把文中的 commit hash 變成可點擊複製的徽章。經 PR #38 合併後發為 1.3.1，視為 patch，因為只動頁面輸出，沒有改動命令、旗標或 JSON 欄位。
- **程式碼行為：** 頁面預設跟隨系統主題；使用者按下切換鈕後選擇會存進 localStorage，下次載入在 body 繪製前就套用，不會閃爍。文中符合 commit 形態的 hash 會變成按鈕，點擊複製，瀏覽器沒有 clipboard 時改為選取文字，讓使用者按 Ctrl/Cmd+C。位於連結內（例如時間軸卡片）的 hash 只是不可點的 span。搜尋框的 / 提示改放進 placeholder。
- **實作方式：** `git_worklog/viewer.py` 把深色調色盤抽成 `_DARK`，同時用於 `@media (prefers-color-scheme: dark)` 搭配 `:root:not([data-theme="light"])`，以及 `:root[data-theme="dark"]`，所以系統深色與手動選深色是同一組顏色；`_page` 新增 `#theme` 按鈕與兩個 svg 圖示；`_JS` 以 `THEME_KEY` 讀寫 localStorage，並在 try/catch 中處理儲存被拒絕的情況。`git_worklog/mdhtml.py` 新增 `_HASH_RE`（7 到 40 位小寫十六進位，不可黏在路徑、識別字或色碼上，使用 ASCII 邊界而非 `\b`，以免 CJK 被視為字元）與 `_AUTHOR_AFTER_RE`，`inline` 內新增 `commit`：數字與字母混合，或寫成 `<hash> (<author>)` 的格式時才算 hash，因此純數字或 defaced 這類全十六進位單字不會被誤判；`links=False` 時輸出 span。這個替換放在 code、連結、autolink 之後，所以不會出現在程式碼或連結 URL 內。
- **影響範圍：** 讀者可以從一句描述直接複製對應 commit，並按偏好固定主題。因為 hash 判定規則偏保守，少數 hash 若既全為數字又不接作者括號，就不會變成徽章。
- **相關檔案：** `git-worklog/git_worklog/mdhtml.py`、`git-worklog/git_worklog/viewer.py`
- **相關 commits：** a990472 (Daniel Hsieh) feat(view): a light/dark switch, and commit hashes as copy badges；c880187 (Daniel Hsieh) Merge pull request #38 from g761007/feat/view-theme-toggle
- **測試與驗證：** tests/test_view.py — 格式規定的 commit 引用變成徽章、全數字 hash 在作者括號下仍算、數字與全十六進位單字保持文字、程式碼、連結與路徑內不產生徽章、連結內為不可點的 span；tests/test_view.py — 主題優先序：手動選擇勝過系統，系統深色與手動深色的調色盤相同，套用記憶主題的 script 位於 body 之前；tests/test_view.py — hash 徽章不會落在 a 標籤內，日內文章才有複製按鈕
- **相容性與風險：** hash 判定是啟發式規則，仍可能誤判看起來像 hash 的十六進位字串，或漏掉只有數字且沒有作者括號的 hash。；主題切換與複製行為在瀏覽器中的互動沒有自動化測試。
- **維護注意事項：** 修改 `_JS` 會改變 script_hash 對應的 CSP 值，這個值是執行時算出的，不需手動同步。；RENDERER_TAGS 白名單在測試中加入了 button 與 span，渲染器新增標籤時要同步更新。
