## 主要異動

### SKILL.md 加入 disable-model-invocation，git-worklog 改為僅由使用者主動觸發

- **異動內容：** `git-worklog/SKILL.md` 的 frontmatter 新增 `disable-model-invocation: true`，把原本列出十幾種觸發語句的多行 `description: >-` 換成一行 `description` 加上新的 `argument-hint`。Claude Code 以外的 host 沒有對應欄位，因此 `git-worklog/agents/openai.yaml` 改用收窄 `description` 與刪減 `ui.keywords` 來降低誤觸發機率。
- **程式碼行為：** 此變更前，模型可以從一般開發對話（例如「整理上一週工作摘要」）自行判斷要不要啟動這個 skill；此變更後，在 Claude Code 上 `disable-model-invocation: true` 讓它從模型的技能清單中整個消失，唯一的進入點是使用者輸入 `/git-worklog`。CLI、JSON 欄位、參數格式都沒有改變，改變的只有「誰來決定要不要開始跑」。
- **實作方式：** frontmatter 的 `description` 改成一行 `Per-day project worklog from real Git diffs, and reports built from it.`，加上 `disable-model-invocation: true` 與 `argument-hint`；本文 §1 明文寫出「使用者才能觸發，模型不可自行觸發」。`agents/openai.yaml` 的 `description` 收窄為一句話、`version` 提升為 1.1.0，`ui.keywords` 拿掉 `release notes`、`git history`、`handoff`、`weekly summary`、`工作摘要`、`週報`，只留下直接指名這個工具的字。`__version__` 從 `1.0.0` 改為 `1.1.0`，`CHANGELOG.md` 新增 `[1.1.0]` 條目與 compare 連結，`README.md` 中英文版都補上「這行你得自己打」的說明。
- **影響範圍：** 原本不打 `/git-worklog` 直接說「整理最近 7 天」的用法在 Claude Code 上不再生效；好處是不會再被跟工作日誌無關的開發對話意外觸發。非 Claude host 沒有等效的停用欄位，只能靠收窄關鍵字降低機率，**並不是**真正做到使用者主動觸發。
- **相關檔案：** `git-worklog/SKILL.md`、`git-worklog/agents/openai.yaml`、`git-worklog/git_worklog/__init__.py`、`README.md`、`CHANGELOG.md`、`tests/test_skill_invocation.py`、`tests/test_version.py`
- **相關 commits：** f8d8c80 (Daniel Hsieh) feat(skill): make git-worklog user-invoked, and put report on the menu
- **測試與驗證：** `tests/test_skill_invocation.py` — 驗證 frontmatter 保留 `disable-model-invocation: true`、具備非空的 `argument-hint`，且 `description` 是不含 `>-` 折疊區塊、長度受限的單行字串；`tests/test_version.py` — 驗證 `__version__` 與 `agents/openai.yaml` 的 `version` 一致並釘住為 1.1.0，同時確認 `LAYOUT_VERSION` 沒有隨產品版本跳號
- **相容性與風險：** 使用者若忘記在請求前打上 `/git-worklog`，模型不會知道這個 skill 存在，只能直接從 `git log` 回答——不讀真正的 diff、不依 tree 檢查證據、不做必要檔案覆蓋率檢查、不產生 dry-run。`CHANGELOG.md` 明白把這個結果稱為「看起來像工作日誌，實際上是這個工具原本要拒絕的 commit 訊息改寫」，並說明這是刻意接受、沒有另外緩解的取捨。
- **維護注意事項：** `disable-model-invocation` 只在 Claude Code 上有效；`agents/openai.yaml` 的收窄描述與關鍵字只能降低其他 host 的誤觸發機率，不能讓那些 host 變成真正的使用者主動觸發，未來若要補上等效機制需另外處理。

### 選單從 7 個選項擴充為 11 個，新增報告選項並統一為英文介面文字

- **異動內容：** 無參數選單從 7 項改為 11 項：`1`-`7` 是原本會寫入 `.git-worklog/` 的產生選項，新增的 `8`-`11` 是唯讀的報告選項（期間摘要、版本 CHANGELOG、指定人員貢獻、待辦技術債）。整份選單改成英文呈現。
- **程式碼行為：** 此變更前，報告模式在選單上完全沒有對應列，只能靠使用者已經知道要用哪句自然語言才能觸發，選單本身只列出 7 個「產生」選項。此變更後，選單涵蓋兩種模式共 11 個選項，`1`-`7` 標示為 `[Generate worklog]`（先 dry-run 才寫入）、`8`-`11` 標示為 `[Report from the existing worklog]`（唯讀、不修改任何檔案）。工作日誌本身的產出語言不受影響，依然跟著對話走。
- **實作方式：** `SKILL.md` §1 的選單本文改成英文並列出 11 個選項，並列出每個選項對應的動作（例如 `10`→**ask who**，絕不用猜的）。`agents/openai.yaml` 的 `default_prompt` 同步改成一模一樣的 11 項選單文字，供無法讀 SKILL.md frontmatter 的 host 使用。`references/interaction-flow.md` 移除原本重複貼在該處的第三份選單文字、改為指向 `SKILL.md` §1 的跨參照，並新增選項 `8`-`11` 的追問對照表——例如選項 `10` 必須追問是誰，不能用 `git config user.name/email` 推斷。`references/report-mode.md` 新增「How a report is reached」段落。`README.md` 中英文版同步展示新選單。
- **影響範圍：** 使用者可以直接從選單選 `8`-`11` 進入報告模式，不必先知道該講哪句自然語言；代價是習慣中文選單的使用者第一次會看到英文介面文字。選單的三份副本減為兩份必要副本，降低未來各自漂移的風險。
- **相關檔案：** `git-worklog/SKILL.md`、`git-worklog/agents/openai.yaml`、`git-worklog/references/interaction-flow.md`、`git-worklog/references/report-mode.md`、`README.md`、`tests/test_skill_invocation.py`
- **相關 commits：** f8d8c80 (Daniel Hsieh) feat(skill): make git-worklog user-invoked, and put report on the menu
- **測試與驗證：** `tests/test_skill_invocation.py` — 比對 `SKILL.md` 與 `agents/openai.yaml` 的選單選項是否逐項一致、兩份都恰好有 11 個選項、編號依序為 1 到 11，並斷言 `references/interaction-flow.md` 不再含有完整選單文字，防止第三份複本再度出現
- **維護注意事項：** 選單有兩份必要複本且無法合併成單一來源——`SKILL.md` 是模型直接印出的文字，`agents/openai.yaml` 的 `default_prompt` 是非 Claude host 當成資料讀取的欄位——未來調整選項時兩處都要一起改，測試會在兩者不一致時失敗。
