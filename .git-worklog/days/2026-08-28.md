## 主要異動

### 驗證範圍改為當日每一個狀態，並把無法檢查的項目與推翻的項目分開

- **異動內容：** Tree 的 day_trees 被換成 day_scope。新版會搜尋 _boundary_parents 找出的當日起始狀態，加上當日所有 commit 的樹；超過 MAX_DAY_TREES 時才退回到起始狀態與 _tips 找出的末端。同時新增 severity 分級：UNVERIFIED_CODES 內的問題（PROSE_SCOPE_TRUNCATED、EVIDENCE_FILE_NOT_TEXT、EVIDENCE_UNVERIFIABLE）只會進入 unverified 清單，不擋日；其餘仍是 blocking。
- **程式碼行為：** 舊版只看當日第一個 commit 的父節點與最後一個 commit，遇到分岔的當日會漏掉另一條線上的名稱，導致正確的名稱被判為 PROSE_SYMBOL_NOT_FOUND。新版的搜尋範圍涵蓋所有 commit，因此中間被建立又刪除的名稱也找得到。當範圍超過上限時會回報 PROSE_SCOPE_TRUNCATED 而不是靜默停止。引用二進位檔（例如 docx）不再讓 collect 整個中斷，而是回報為 EVIDENCE_FILE_NOT_TEXT 並附上 commit 與路徑。
- **實作方式：** prime 以單一次 git grep -o 批次回答整份結果的所有 token，且 git 回傳錯誤碼大於 1 時不寫入快取，避免把錯誤誤記為缺席。Tree._git_bytes 以位元組讀取 git 輸出，file_at 自行做嚴格 UTF-8 解碼，非文字時回傳 NOT_TEXT，並在 _verify_against_tree 中轉為 EVIDENCE_FILE_NOT_TEXT。_stamp 依 UNVERIFIED_CODES 為每個 issue 標上 severity。validate 會呼叫 _all_prose_tokens 取得全部 token 再 prime，超過範圍上限時發出 PROSE_SCOPE_TRUNCATED。read_run 把只含 unverified 的日子放進 unverified 清單，但仍收入 results。render_text 會印出 unchecked 行，preview 的 build 透過 _with_unverified 把 unverified 併入 warnings。
- **影響範圍：** collect 的判定、preview 的警告與 analyze 的文字輸出都會改變。日子是否被擋只看 blocking 項目，因此淺複製或二進位引用不再讓整個 run 變成 partial。validate_prose 仍以 PROSE_SYMBOL_NOT_FOUND 擋下真正捏造的名稱。
- **相關檔案：** `git-worklog/git_worklog/analysis/results.py`、`git-worklog/git_worklog/cli/analyze.py`、`git-worklog/git_worklog/preview.py`
- **相關 commits：** d837969 (Daniel Hsieh) fix(analysis): search every state a day passed through, not its ends；40a6b7d (Daniel Hsieh) Merge pull request #36 from g761007/fix/day-trees-multi-line
- **測試與驗證：** tests/test_prose_symbols.py 涵蓋 day_scope 的範圍、分岔日（TestAForkedDay）、中間態名稱（TestASymbolThatOnlyExistedMidDay）、prime 與逐一查詢結果一致，以及 git 拒絕時不寫入快取；tests/test_day_results.py 涵蓋淺複製時只回報 unverified 而不擋日（TestShallowCloneCannotVerify），以及二進位引用只回報 EVIDENCE_FILE_NOT_TEXT 而不擋日（TestBinaryEvidenceIsUnverifiableNotFatal）
- **相容性與風險：** prime 依賴 git grep -o 在 -w -F 下輸出的匹配文字即為 token 本身，這是依原始碼註解與測試推論的假設，本分析沒有執行測試確認；超過上限的日子只搜尋起點與末端，中間態的名稱可能未被檢查，但會以 PROSE_SCOPE_TRUNCATED 標示
- **維護注意事項：** 舊名稱 day_trees 在本日的測試中已全數改為 day_scope，後續若要引用舊介面需同步修正
