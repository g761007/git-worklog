## 主要異動

### view 的 commit 抽屜與 --serve 本機伺服模式（1.5.0）

- **異動內容：** 日誌頁上的 commit hash badge 原本只能複製；這一天讓它在 Git 認得該 hash 時開啟右側抽屜，顯示 commit 訊息、作者、日期與檔案清單，並在 view --serve 模式下可展開單檔 diff。靜態頁仍然只內嵌摘要，不內嵌 diff。
- **程式碼行為：** git-worklog view 現在會唯讀地詢問 Git：日誌引用的 token 若解析成 commit，badge 點擊就開抽屜（複製改為抽屜內按鈕）；Git 不認得的 hash（被 rebase 掉、日誌所在目錄不是 repo 頂層、淺層 clone）維持點擊即複製。新增互斥旗標 --serve（與 --output 擇一）：綁定 127.0.0.1 的隨機埠、網址帶本次執行的 token，先輸出完整 JSON 再持續服務直到 Ctrl+C。JSON 多了 commit_count 與 serving 欄位。
- **實作方式：** 新檔 `git_worklog/analysis/commits.py`：`owns` 要求目錄必須就是 Git 工作樹頂層（避免日誌放在無關的上層 repo 時解析到別人的 hash 或 diff）；`collect` 以 `_batch_resolve` 把 token 解成完整 sha，再用一次 `git log --no-walk --stdin` 取 numstat，`_parse` 解析 NUL／記錄分隔的輸出，檔案數與訊息內文各有上限（MAX_FILES、MAX_BODY）；`DIFF_FLAGS` 讓 merge 以 first-parent 顯示、不檢查簽章。`viewer.build` 新增 repo、diff_base 參數，`_tokens` 合併 `cited_hashes` 與 `mdhtml.HASH_RE`（原 _HASH_RE 改為公開名稱）兩種掃描結果，`_commit_data` 把 commit 資料放進 type 為 application/json 的 script 區塊並跳脫「<」，頁面 CSP 只在有 diff_base 時才加 connect-src 'self'。前端 JS 新增 drawer、openCommit、loadDiff 與快取、Esc 關閉、焦點還原。新檔 `git_worklog/viewserver.py`：`Server` 繼承 ThreadingHTTPServer 只綁 127.0.0.1，`_Handler.do_GET` 檢查 Host 標頭（403，防 DNS rebinding）、以 secrets.compare_digest 比對路徑 token（404）、只回應頁面目前引用的 commit 的 diff；`diff` 以 Popen 讀取並在讀取時就套用 2 MiB 上限，並停用 ext-diff 與 textconv。`cli/view.py` 新增 `_serve`、`_open`、`after_emit`，`cli/__init__.py` 的 main 在輸出後呼叫指令的 after_emit 鉤子，使 view --serve 成為唯一「輸出後仍持續執行」的指令。
- **影響範圍：** 讀日誌的人可以從句子直接追到 commit 與其 diff，不必回終端機跑 git show。同時這改變了先前計畫中「view 不呼叫 git」與「不開伺服器」兩個決策，但伺服模式是 opt-in，預設仍是靜態單檔。
- **相關檔案：** `git-worklog/git_worklog/analysis/commits.py`、`git-worklog/git_worklog/viewserver.py`、`git-worklog/git_worklog/viewer.py`、`git-worklog/git_worklog/cli/view.py`、`git-worklog/git_worklog/cli/__init__.py`、`git-worklog/git_worklog/mdhtml.py`、`tests/test_view.py`
- **相關 commits：** 60ac9af (Daniel Hsieh) feat(view): open a commit from its hash, and serve diffs with --serve；21ef46b (Daniel Hsieh) test(view): pin what the page embeds and what --serve answers；e66d016 (Daniel Hsieh) Merge pull request #40 from g761007/feat/view-commit-drawer
- **測試與驗證：** tests/test_view.py — Git 對被引用 commit 的描述、只詢問日誌所在的 repo、過多檔案時列出部分但計入全部、頁面只內嵌被引用的 commit、commit 訊息無法跳出資料區塊、無 Git 時頁面維持原樣、只有伺服頁可以 fetch、指令回報 commit 數；tests/test_view.py — view --serve：只監聽 loopback、token 為唯一入口、錯誤 Host 被拒、未被引用的 commit 不提供、只讀、過大的 diff 被截斷並標示、--serve 與寫檔互斥、先輸出 JSON 再持續服務
- **相容性與風險：** 伺服模式把原始碼 diff 經本機 HTTP 提供；防護靠 127.0.0.1、token、Host 檢查與只服務被引用 commit，網址（含 token）會留在瀏覽器歷史與輸出中，程式內的 SERVE_NOTE 已提醒這點。；前端 JS 與 CSS 是內嵌字串，抽屜的互動行為只有在測試能檢查的範圍（內嵌資料、CSP、回應）被驗證；瀏覽器端互動本次我只讀了程式碼，沒有執行。
- **維護注意事項：** 指令若要在輸出後持續執行，請走 after_emit 鉤子，並確保輸出已 flush。；git-worklog/SKILL.md 的指令表已註明不要由 agent 自行執行 view --serve，因為它不會自行返回。

### 使用者自己的模型表與 git-worklog models 指令（1.6.0）

- **異動內容：** subagent 使用的模型表從套件內的 provider_models.json 改為讀取使用者的 ~/.git-worklog/provider_models.json：第一次解析模型時由出貨預設值複製出去，之後絕不改寫；並新增 models 指令讓 agent 或使用者以 dry-run 優先的方式修改。
- **程式碼行為：** resolve 在未指定 config_path 時會呼叫 ensure_user_config：檔案不存在就以 seed 的內容寫出，並回報一次 USER_MODELS_CREATED 警告，內容指示 agent 先詢問使用者是否更新為 host 目前的模型；若家目錄無法寫入則讀出貨表並回報 USER_MODELS_NOT_WRITTEN。使用者的檔案壞了就是錯誤，不會悄悄退回出貨預設。新指令 models：不帶 --host 只顯示（含與出貨預設的差異）；帶 --host 與欄位則先 dry-run，加 --apply 才寫入，只改指定 host 的指定欄位，其他鍵保持原樣；改了 model 而沒給 display-name 時，display_name 跟著模型 id 走。doctor 新增 provider_models 檢查，差異只是警告並逐欄列出。resolve_provider_model.py 的 --config 預設改為 None 以走使用者的檔案。
- **實作方式：** `providers.py` 新增 `write_user_config`（暫存檔加 os.replace，整檔寫入或不寫）、`seed`、`ensure_user_config`、`differences`，並讓 `load_config` 驗證 providers 物件且錯誤帶 target；`paths.py` 新增 `models_path`；`cli/models.py` 的 `run` 以 `FIELDS` 對應 argparse 目的地與表中欄位，錯誤碼包含 ARG_CONFLICT、UNKNOWN_HOST、IO_ERROR；`cli/doctor.py` 的 `_check_provider_models` 比對使用者表與出貨表；`cli/__init__.py` 註冊 models 子指令。
- **影響範圍：** 新模型上線不必等工具發版，改使用者檔案即可；升級也不會改掉使用者的選擇，代價是出貨預設會老化，因此以首次建立警告與 doctor 差異清單來提醒。
- **相關檔案：** `git-worklog/git_worklog/providers.py`、`git-worklog/git_worklog/paths.py`、`git-worklog/git_worklog/cli/models.py`、`git-worklog/git_worklog/cli/doctor.py`、`git-worklog/git_worklog/cli/__init__.py`、`git-worklog/scripts/resolve_provider_model.py`、`tests/helpers.py`、`tests/test_provider_models.py`
