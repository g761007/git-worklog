## 當日摘要
<!-- GIT_WORKLOG:SUMMARY:START -->
查出並修掉「subagent 的 Write 呼叫會憑空消失、導致整天分析遺失」的根因，改以加引號的 Bash heredoc 交付結果，同一天連發 1.2.0 與 1.2.1——後者補的正是 1.2.0 上線後第一次真實使用自己抓出來的洞。
<!-- GIT_WORKLOG:SUMMARY:END -->

根因是 subagent 呼叫 `Write` 時該次呼叫憑空消失：沒有 tool_result、沒有錯誤、沒有檔案，而且在它的下一輪對話裡那次呼叫視同從未發生。因為 subagent 感知到的不是「寫入失敗」而是「我還沒寫」，任何偵測式的保險條款都無從觸發。契約把機制釘死成 `cat > <path> <<'GIT_WORKLOG_JSON_EOF'`，並要求寫完自我驗證。1.2.0 發布後隨即用它替今天產生日誌，當場暴露 1.2.0 只禁 `Write` 沒禁 `Edit`——subagent 驗證抓到錯之後伸手用 `Edit` 修，同樣消失，於是 1.2.1 把 `Edit` 一併禁掉、修復方式改成整檔重寫，並要求 JSON 字串值裡的雙引號跳脫。另外把 git 黃金法則從「絕不執行」澄清為「絕不主動執行」。

### Subagent 結果交付機制根因修復：改用加引號的 Bash heredoc，禁用 Write 工具

- **異動內容：** 修正造成連續多次分析結果整天遺失的根因。subagent 呼叫 `Write` 工具寫入結果檔時，該次呼叫會憑空消失——沒有 tool_result、沒有錯誤、也沒有檔案，而且在下一輪對話裡這次呼叫視同從未發生。
- **程式碼行為：** 兩份 prompt 樣板（Day Subagent 與 Code Analysis Subagent）不再只籠統要求「寫一個檔案」，而是明確禁止 `Write`、規定 heredoc 的確切形狀（分隔符必須加單引號、結尾必須從第 0 欄開始），並加入寫完自我驗證、失敗可回覆 `FAILED:<date>` 的步驟。
- **實作方式：** `references/subagent-contract.md` 的 §6a 新增一節解釋這個性質為何讓自我偵測與 fallback 都不可行，並釘住寫法 `cat > <result_path> <<'GIT_WORKLOG_JSON_EOF'`；§9、§10 的樣板本文改寫成含 heredoc 範例與工具禁令的完整段落。`SKILL.md` §3c 與 §7 同步：§3c 講清機制與禁令，§7 新增可執行的診斷——某天回報 `missing` 且其 `result_path` 在磁碟上根本不存在，代表該 subagent 用了 `Write`，處置是照 §9 樣板把 heredoc 區塊原樣重貼後重新派工，而不是手動補檔或重跑 `analyze prepare`。
- **影響範圍：** 不改變任何終端使用者可見的指令、旗標或 JSON 欄位；但對「一天的分析會不會整份憑空消失」是關鍵修復——此前三次真實派工都栽在同一個 `Write` 呼叫上。
